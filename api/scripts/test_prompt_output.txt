Ты создаёшь полноценную категорию для турнирной игры на выбор любимых вариантов.

ИГРА: пользователю показываются пары (X или Y), он тапает любимое, побеждённый отсеивается, в финале определяется один №1 + №2 + №3. После турнира юзеру показывается «типаж» — образ-портрет на основе его top-3.

ЗАЯВКА ОТ ИГРОКА (нужно превратить в полноценную категорию):
- Название: Лучший сериал всех времён
- Что выбираем (описание): Сериалы которые стоит пересмотреть
- Кластер от автора: Сериалы
- Примеры от автора: Breaking Bad, Игра престолов, Friends, The Office

ТВОЯ ЗАДАЧА: написать полную JSON-структуру категории, готовую к публикации, ВКЛЮЧАЯ архетипы.

ПРАВИЛА ПО СОДЕРЖИМОМУ:

1. Ровно 16 items (если естественный размер темы 8/32/64 — используй его). recommended_tournament_size = длина items.
2. items[].name — настоящие, существующие в реальности (не выдумывай). Используй свои знания мира.
3. items[].ctx — короткая подпись, в стиле «факт1 · факт2» или «год · оскар · фильм» или подобное. Длина 30-60 символов. Пиши только реальные факты.
4. items[].id — латиница в kebab-case, уникальный в пределах категории, происходит от имени.
5. id категории — латиница snake_case, короткая, уникальная.
6. blurb — одна строка-подзаголовок, отвечает на вопрос «что выбираем» (1-7 слов).

ПРАВИЛА ПО ЛОКАЛИЗАЦИИ (двуязычная категория RU + EN):

L1. Каждое поле, видимое игроку, дублируется по-английски с суффиксом _en:
    name → name_en, blurb → blurb_en, items[].name → items[].name_en, items[].ctx → items[].ctx_en,
    archetypes[].name → archetypes[].name_en, archetypes[].body → archetypes[].body_en,
    defaultArchetype.name → defaultArchetype.name_en, defaultArchetype.body → defaultArchetype.body_en.
L2. EN-версия — это ПЕРЕВОД, а не пересказ. Сохраняй смысл, имена реальных вещей оставляй в международной форме.
L3. Стилистически EN-тексты должны звучать как написанные нативом, а не машинный перевод.
L4. Архетипы EN — те же 4 параграфа, тот же tone-of-voice (на «you»), 600-900 символов.
L5. items[].id, archetypes[].triggers, ключи структуры — только латиница, остаются БЕЗ изменений в обоих языках.

ПРАВИЛА ПО КЛАСТЕРУ:

7. cluster — выбери ПОДХОДЯЩИЙ из существующих: Кино / Сериалы / Мультфильмы / Аниме / Музыка / Книги / Игры / Еда / Напитки / Места / Животные / Спорт / Развлечения / Стиль / Технологии / Профессии / Люди.
   Если ни один по смыслу не подходит — придумай НОВОЕ короткое русское название кластера (1-2 слова).

ПРАВИЛА ПО АРХЕТИПАМ:

9. archetypes — массив 6-10 архетипов, каждый со свойствами {name, name_en, body, body_en, triggers}.
10. archetypes[].name — МЕТАФОРА-ОБРАЗ, не термин. Краткое имя 1-3 слова.
11. archetypes[].body — текст 800-1200 символов на ОБОИХ языках, ровно 4 параграфа, разделённых \n\n:
    п.1 (200-300 chars) Кто ты в одном движении. Открой конкретной сценой или образом, не определением.
    п.2 (200-300 chars) Что это значит на самом деле — механизм, а не штамп.
    п.3 (200-300 chars) Как ты выглядишь со стороны — конкретная реакция окружающих.
    п.4 (200-300 chars) Что стоит знать — КОНКРЕТНЫЙ практический риск + одна осмысленная подсказка.
12. archetypes[].triggers — массив 2-5 item id, которые буквально олицетворяют этот архетип.
    Триггеры подчиняются жёстким правилам распределения — см. отдельный блок «ПРАВИЛА ПО TRIGGERS» ниже.
13. defaultArchetype {name, name_en, body, body_en} — fallback на случай редкой комбинации топ-3.

ПРАВИЛА ПО TRIGGERS (это математика игры — нарушения = провал архетипа):

T1. Каждый item ОБЯЗАН быть в triggers как минимум одного архетипа.
    Item, не попавший ни в один архетип, не может повлиять на результат —
    его выбор юзером ничего не значит для движка. Это баг, а не фича.

T2. Каждый item НЕ ДОЛЖЕН быть в triggers более чем 2 архетипов.
    Если item «подходит» 3+ архетипам — значит архетипы плохо разделены
    семантически. Переделай архетипы так, чтобы у каждого item было
    максимум 2 «родных» архетипа.

T3. Длина triggers одного архетипа: 2-5 items. НЕ больше 5.
    Если хочется сделать архетип с 6+ триггерами — значит он слишком
    общий, разбей его на два более узких. Архетип, под который подходит
    треть всей категории, заглушает все остальные.

T4. Архетипы должны быть СЕМАНТИЧЕСКИ НЕЗАВИСИМЫ.
    Если у двух архетипов больше 50% общих triggers — это один архетип,
    объедини их или переформулируй один так, чтобы пересечение стало ≤30%.

T5. Триггеры архетипа = только те items, которые БУКВАЛЬНО олицетворяют
    суть этого архетипа. Тест: можно ли сказать про item —
    «это идеальный пример {архетипа}»? Если «ну, наверное, тоже подходит» —
    НЕ КЛАДИ. Лучше пусть item висит у одного архетипа, чем у трёх.

T6. ОБЯЗАТЕЛЬНАЯ САМОПРОВЕРКА ПЕРЕД ВЫДАЧЕЙ JSON:
    a) Для каждого item посчитай, сколько раз он встречается в triggers
       всех архетипов. Число должно быть 1 или 2.
       Если 0 — добавь в подходящий архетип. Если 3+ — убери из лишних.
    b) Для каждого архетипа посчитай длину triggers.
       Число должно быть 2-5. Если >5 — разбей архетип. Если <2 —
       либо добавь триггер, либо убери архетип целиком.
    c) Если хотя бы одна проверка не сходится — переделай triggers
       и проверь снова. Не выдавай JSON, пока всё не сойдётся.

ПРАВИЛА ПО ГИБРИДНОЙ СКЛЕЙКЕ (87-95% юзеров видят гибрид — это основной
рендер результата, не edge case. Движок берёт п1 одного архетипа + п1
другого + склеивает между intro и outro):

H1. п1 каждого архетипа — САМОСТОЯТЕЛЬНЫЙ мини-текст. Запрет на связки
    «Это значит / Поэтому / Как уже сказано / И вот почему / То есть».

H2. РАЗНООБРАЗИЕ ОТКРЫТИЙ. Среди архетипов категории не больше 40%
    могут открываться шаблоном «Тебе нравится / Ты любишь / Тебя X».
    Остальные открой через: конкретную сцену / item-list / парадокс /
    прямую речь окружающих / антитезу.

H3. п1 заканчивается ЗАКРЫТЫМ беатом. Не «...об этом дальше».

H4. SPLICE-TEST перед выдачей JSON: возьми 2-3 случайные пары архетипов,
    мысленно склей их п1 через intro+outro template. Если читается как
    самоповтор или одинаковая структура — переделай п1 хотя бы у одного.

H5. Подсчитай % п1 начинающихся с «Ты / Тебе / Тебя» в первых 1-3 словах.
    Должно быть ≤40%. Если больше — разнообразь.

H6. EN-версия п1 подчиняется тем же правилам H1-H5. Если RU п1 открыт
    сценой, EN п1 тоже открой сценой. Splice-test и для EN.

ПРОЧЕЕ:

14. category_type — "general" если про объективные предпочтения, "personal" если про самого юзера.
15. category_subtype — entertainment / personal / dating / brand / experimental / social / media / music / fashion / philosophy / education / career / tech / gaming / ru_cis.
16. is_experimental — false (если категория обычная).

ВАЖНО:
- Отвечай ТОЛЬКО строгим JSON-объектом. Никакого markdown ```json``` обрамления, никаких пояснений до или после.
- Каждое user-facing поле должно идти ПАРОЙ: русский оригинал + английская версия с суффиксом _en.
- Никаких выдуманных фактов в ctx/ctx_en — только реальные.
- Items не должны повторяться. Должно быть разнообразие.
- ОБЯЗАТЕЛЬНО: каждый item — в triggers 1-2 архетипов (не 0, не 3+). Каждый архетип — 2-5 triggers (не больше). См. блок «ПРАВИЛА ПО TRIGGERS».
- Сделай самопроверку T6 перед выдачей JSON. Это важнее чем красивый текст.
